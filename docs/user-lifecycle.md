# 按入站管理用户与 AnyTLS 生命周期

本改动实现节点内部的用户管理基础，并使用真实 TLS/AnyTLS 连接验证。[原生配置入口](native-config.md)现已支持显式 `coreType=singbox`，具备管理 API 的构建发布相应能力。配套修改版 Panel 已完成 Profile、权限、用户下发及 AnyTLS 订阅接入。

## 状态与授权

状态按配置代次、输入格式、入站 tag 和稳定用户 ID 保存。UUID／密码、VLESS flow 和 hash 别名均为用户属性。候选快照与已提交状态互不共享可变 map；失败请求不会先修改用户表。

- 单用户请求替换该用户在本节点的完整授权集合。
- 批量请求只替换本批用户，保留其他用户；`affectedInboundTags` 不会清空整批入站。
- 删除按稳定用户 ID 跨纳管入站执行；hash／旧 UUID 用于兼容定位和身份一致性检查。缺少可解析身份、同批重复用户、重复 tag、未知入站、协议不匹配、重复凭据、空凭据等请求明确失败。
- 单／批量 AnyTLS 使用稳定用户 ID 作为 `name`；批量 password 使用 `vlessUuid`。单用户 password 由契约字段传入。
- SS2022 单用户仍传原始 `password`，批量仍对 `ssPassword` 做 base64；保留官方两条请求路径的既有差异。更新前校验密钥长度，保留内核对较长密钥的派生语义。
- Xray 兼容输入沿用空 VLESS flow 默认 Vision 的行为；原生格式状态保留显式空 flow，避免后续原生路径被强制改写。

Xray 全量配置也按每个入站自己的 clients 提取用户，修正原来同协议用户集合互相串用的问题。SS2022 的空 clients 保持为可热更新的空多用户入站，不退回共享 PSK 单密码模式。

## 应用与失败

配置和用户请求共用节点控制锁串行处理。用户请求在更新完成后返回结果；取消原先先成功响应、之后 debounce 应用的流程。`SINGBOX_DEBOUNCE_MS` 仍接受原有配置值以兼容部署，但不再延迟用户应用。

内核先校验整个候选集合和所有目标入站的更新接口，再逐个应用。若某个更新失败，恢复所有已尝试的入站，包括可能已经部分变更的失败目标。恢复失败则关闭当前内核并报告错误，等待全量配置恢复，不能假装旧状态仍正常运行。多入站更新不是数据面的瞬时原子切换；已关闭的会话不能通过回滚重新打开。

`forceRestart=false` 的全量推送按实际有效配置比较：只有用户变化时热更新，即使原始请求与此前保存内容相同，也会恢复其权威用户集合。路由、监听、证书等基础配置变化或 `forceRestart=true` 仍重建实例。回滚配置同步保存成功的用户变更和统计名单。

VLESS/SS2022 活动连接关闭继续通过现有 Clash API 和白名单语义执行；失败现在明确返回，并保存待重试集合。AnyTLS 身份撤销由协议服务直接关闭认证会话，不依赖在线列表，也不会跳过回环或白名单用户。

## AnyTLS 实现

本地 [入站适配器](../internal/protocol/anytls/PROVENANCE.md) 基于锁定 fork 的实际源码及更新接口，通过内核 registry 注册；[依赖补丁](../third_party/sing-anytls/RWNODE_PATCH.md) 固定在 v0.0.11，并保留源码来源和许可证。没有引入外部 sing-box 进程。

鉴权表和会话注册共用同步机制。每个有效身份有不可变代次：相同配置重试保留会话；删除后重新添加同一密码也不会使早前已取得旧代次的握手重新生效。删除、轮换或改变身份会同步关闭该身份的活动流及空闲认证会话；其他用户和其他授权入站的会话保留。关停还会关闭正在等待协议认证的连接。

并发测试发现并修复了流错误状态、客户端关闭回调、会话版本及缓冲状态的相关竞争，原先只给 `UpdateUsers` 加锁不足以覆盖这些路径。

统计继续使用稳定用户 ID。热更新同步 v2ray_api 用户名单；删除用户不清除尚未上报的计数。AnyTLS 路由元数据保留入站、用户及源 IP，供现有 Clash 在线查询使用。空闲认证会话不计为活跃代理流，但仍受撤销管理。

## 验证范围

- 状态：授权缩减、跨协议轮换、批量保留其他用户、身份冲突、幂等重试、旧代次拒绝。
- 实际 handler → App → 内核 → TLS/AnyTLS：活动流撤销、空闲会话撤销、密码轮换、无权限入站拒绝、其他用户会话保持。
- 实际内核：新用户统计、在线用户/IP、删除后计数保留、更新不重建内核。
- Xray 输入／SS2022：多入站隔离、相同全量请求恢复用户、并发重试、空用户及失败回滚后共享 PSK 不可用。
- 用户批次更新失败及恢复失败使用故障注入验证；构建、vet、普通测试、发布标签 race 测试和依赖 race 测试作为回归检查。

部署联调已验证实际 Panel／数据库／队列同步、AnyTLS 订阅客户端连接、原生 VLESS Reality/Vision、权限撤销与节点重启恢复。尚未进行长期高负载测试，也不代表任意客户端版本及全部上游协议均兼容。
